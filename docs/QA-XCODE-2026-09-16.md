# Validación con Xcode — 16 de septiembre de 2026

Resultado: comprobaciones de Safari y PWA indicadas abajo aprobadas en simulador.
No equivale a validar un iPhone físico ni el flujo autenticado de un cliente real.
Los puntos 2–4 (ayuda real, catálogo y acceso/piloto de Santiago) se aplazan por
instrucción del dueño. No se modificó código de producto ni datos reales.

## Entorno

- Xcode 27.0, build 27A266a; simulador QA iPhone 16 Pro, iOS 27.0,

## Comprobaciones ejecutadas

| Comprobación | Resultado observado |
| --- | --- |
| Bienvenida y ayuda | Abrir entrenamiento, cerrar consejo y navegar libremente. |
| Más opciones | Despliegue dentro del contenido; desplazar hasta Cerrar opciones y cerrar correctamente. El botón puede requerir scroll. |
| Teclado Safari | Peso decimal 42.5 introducido con teclado numérico de iOS y cierre mediante la marca de confirmación del teclado. |
| Guardar serie Safari | Guarda 42.5 lb/lado, 1 rep y RIR 2; siguiente serie muestra 42.5. |
| Descanso automático | Al guardar aparece 2:59 de un descanso de 3 minutos. +30s y Omitir responden. |
| Segundo plano Safari | Home y regreso sin terminar Safari: contador 2:46, serie conservada; no se reinicia a 3:00. |
| Instalación PWA | Compartir → View More → Add to Home Screen → Open as Web App activo → Add. Icono Santiago FM presente. |
| Apertura instalada | Abre portada sin barras de Safari, coherente con start_url `/`. Explorar el método abre la demo. |
| Entrenamiento PWA | Introducir 5 reps, cerrar teclado y guardar: registro 5, siguiente serie 5 y descanso automático. |
| Corrección PWA | Omitir descanso, editar primera serie de 5 a 4 y guardar; no inicia otro descanso. |
| Navegación PWA | Volver al resumen conserva 1 de 16 series; Biblioteca y Progreso accesibles. |

No se observó bloqueo del flujo en estas comprobaciones. Los primeros intentos
de automatización fallaron por tocar elementos fuera del área visible o por
coordenadas incorrectas de la hoja nativa Compartir. Se repitieron con controles
visibles y capturas. `hideKeyboard` no funcionó en Maestro; la marca de confirmación
del teclado sí. Un lanzamiento de Safari mediante Xcode lo reinició y reinició la
demo; la prueba de segundo plano se repitió con `launchApp: {stopApp: false}`.
